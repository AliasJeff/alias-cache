Nothing you got an OK for is ever lost.

alias-cache is a Redis-compatible key-value store where your data doesn't disappear. Every write is replicated to a Raft majority before the client gets its OK, so a crashed leader or a network partition can't quietly drop data you were told was written. It speaks RESP2 and RESP3, so the Redis clients you already use connect without changes.

Why alias-cache

Why not just run Redis with replicas?

Because Redis replication is asynchronous: the leader answers the client before the replicas have the write. If the leader dies in that window, the failover promotes a replica that never saw writes the client was already told succeeded.

✗ Redis with async replicas

The leader sends OK first and replicates after. When it dies in between, the new leader doesn't have the write, and the data the client was told about is gone.

✓ alias-cache with Raft

The write is committed on a majority first; the OK goes out second. A failover promotes a replica that already holds every acknowledged write, so nothing comes back missing.

Features

What you get

The data types and commands most Redis applications use, backed by majority replication.

🛡️

Durability that survives failover

Every acknowledged write is on a Raft quorum. Leader death, network partitions, node restarts: nothing acknowledged is lost.

📖

Linearizable reads at scale

Lease-based reads serve straight from the leader's state machine at ~372k GETs/s, falling back to ReadIndex with fail-closed semantics under partitions.

🔌

Works with standard Redis clients

Full RESP2 / RESP3: pipelines, inline commands, HELLO negotiation. Standard clients connect without modification.

🧱

Rich data types

Strings with the full SET option matrix, Hash, List, Set, Sorted Set, Bitmap including BITOP, Streams, and Bloom filters with deterministic cross-replica hashing.

🔒

Transactions without races

MULTI/EXEC with WATCH: the CAS check and the writes commit in the same log entry — no check-then-write window on any replica.

📜

Sandboxed Lua scripting

EVAL runs on the leader with a memory cap and an instruction budget, and only the deterministic result is replicated.

⏱️

Timing-wheel TTL

A hierarchical timing wheel tracks every TTL'd key with O(1) amortized discovery; mass expiration is reclaimed in one log entry, not one per key.

⚡

Fast crash recovery

Incremental snapshots — a durable base plus delta segments — bring a restarted node back in seconds, not minutes.

🧰

Security & operations

Password auth, client TLS, mTLS for replication traffic, max-memory and max-connection limits, five-section INFO, Sentinel-style discovery, and idempotent retries via client request IDs.

The write path

How it stays fast

The implementation details behind the numbers above — what the leader does with every write, stage by stage.

1

Pipelining

Commands arrive in pipelines, so a connection keeps many requests in flight instead of waiting on each reply.

2

Group commit

The leader merges writes from many connections into one batched commit. When traffic goes quiet, the batch flushes early so reads aren't stuck behind it.

3

raft-engine WAL

The write-ahead log is TiKV's raft-engine with group-commit fsync. Throughput doesn't decay as the log grows.

4

Pipelined replication

Each follower link is one persistent connection with a bounded number of appends in flight and in-order replies, not one round trip at a time.

5

Commit, then ack

Once a majority has the entry, the client gets its OK. Incremental snapshots bring a restarted node back in seconds.

Quick start

1 · Single node 
cargo build --release
./target/release/alias-cache-cli --node-id 1

# any Redis client works — RESP2 and RESP3
redis-cli -p 6379 SET hello world
redis-cli -p 6379 GET hello
2 · Docker, 3-node cluster 
docker compose up --build --detach

Or wire three nodes by hand for automatic failover — the exact commands are in the README.

Verify it yourself 
cargo test --workspace --locked      # 181 tests, incl. OpenRaft's storage contract suite
python3 scripts/smoke_cluster.py     # real 3-node failover: kill the leader, watch recovery

Prefer binaries? Prebuilt linux-amd64 / linux-arm64 / darwin-arm64 / darwin-x64 builds are on the Releases page.
